Why I ship every analysis as a single HTML file

19 Nov 2026·5 min read·Ideas

Look at my GitHub and you'll notice a pattern: almost every project ends in an index.html. A survival analysis, a fuel heat map, a cost map, a trip-distance report. Each one is a single page that opens in any browser and needs no server.

That's deliberate. This post explains why.

1. The audience is on a phone

Operations managers aren't sitting in a BI tool. They're in the field, in meetings, or on WhatsApp. A file they can open with one tap gets looked at. A dashboard behind a login, a VPN and a licence usually doesn't.

2. A snapshot is a feature, not a bug

Live dashboards keep changing. That's great for monitoring and bad for decisions. When a manager says "the report showed 316 offline devices", everyone should be able to open the same report and see 316. A dated, static page becomes a record of what we knew and when.

3. Nothing to maintain

No server to patch, no database connection to break and no API key to rotate. I inline the libraries, such as Leaflet and the heat-map plugin, and embed the data in the page, so it keeps working years later. GitHub Pages hosts it for free.

4. Privacy is easier to reason about

Because the data is baked in, I know exactly what's exposed: only what I put there. Before anything goes public I strip plates, IMEIs and company names, replace clients with codes, and coarsen coordinates to between 110 m and 1 km. With a static page there's no risk of an API quietly returning more than I intended.

5. Bilingual from the start

Many of my readers prefer Arabic. A static page makes it easy to ship index.html in Arabic (RTL) next to en.html in English, with a toggle between them. It's the same data with a different audience.

The best analysis is the one people actually open.

When I wouldn't do this

Real-time monitoring, alerting, and anything where many people edit data together still need a proper application. For answering a single question and sharing the answer, though, a single HTML file is hard to beat.

The site you're reading is built the same way: plain HTML and CSS with no framework.
